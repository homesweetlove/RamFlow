# 제한된 메모리 환경 성능 검증 계획

> **상태: 검증 프로토콜 / 실사용 결과 미기입.** 이 문서는 벤치마크 계획이지 성능 향상 실험 결과가 아닙니다.

## 검증 질문

“기존 RAM을 최대한 활용한다”는 목표를 **사용자의 작업 경험**으로 판단합니다.

1. 같은 PC·같은 작업에서 활성 앱의 실행·전환·작업 완료 시간이 단축되는가?
2. 메모리 압박 시 Commit, Available RAM, 페이지 입출력의 변화가 사용자 경험과 일치하는가?
3. 백그라운드 앱 복귀 시 재로딩이나 멈춤 등의 **역효과**가 증가하지 않는가?
4. RamFlow 자신이 사용하는 메모리·CPU와 복원 비용을 포함해 순효과가 있는가?

RAM 사용량 숫자 하나가 낮아졌거나 Working Set이 감소했다는 사실만으로 성능 향상을 주장하지 않습니다. Windows는 접근이 필요한 페이지를 다시 불러올 수 있습니다.

## 대상 환경과 실험 조건

- 우선 실제 8 GB Windows PC에서 측정하고, 가능한 경우 별도의 16 GB PC에서 재현합니다. 실험 PC의 정확한 RAM 용량, Windows 빌드, CPU, 저장장치, 페이지 파일 설정, RamFlow 버전, 앱 버전을 기록합니다.
- **A (기준):** RamFlow 완전 종료. Windows 기본 정책 상태.
- **B (관측 비용):** RamFlow 실행, Dry Run 활성화. 실제 조정 없이 앱 자체 오버헤드 관측.
- **C (실제 조정):** 관리자 권한에서 사용자가 명시적으로 승인한 제한적 정책. 개입 조건 충족 여부와 조정·복원 로그를 기록합니다.
- A/B/C 각각 5회 이상 반복합니다. 캐시·부팅 상태·작업 순서로 인한 편향을 줄이도록 조건 순서를 교차하고, 매 반복 사이 시작 상태를 맞춥니다.
- Windows Update, 다운로드, 실시간 백업 등 외부 요인을 가능하면 중단하거나 기록합니다. 같은 브라우저 탭, IDE 프로젝트, 작업 파일, 시작 조건을 사용합니다.
- 가급적 UI 조작을 스크립트화하되, 실행 시간과 지연 시간은 테스트 장비에서만 측정합니다. 측정값이 없는 항목은 미측정으로 남깁니다.

## 실제 사용 시나리오

| 시나리오 | 작업 | 사용자 관점의 핵심 지표 |
| --- | --- | --- |
| 멀티태스킹 | 브라우저 여러 탭 + IDE + 문서 앱 전환 | 활성 앱 전환 지연, 다시 그리기·새로고침 발생 |
| 개발 작업 | IDE에서 동일 프로젝트 열기·검색·빌드 | 빌드 완료 시간, IDE 응답성 |
| 메모리 압박 | 메모리 부족이 관찰되는 실제 작업 조합 유지 | 압박 상태, 페이지 입출력, 앱 전환 지연 |
| 복귀 비용 | 오래 비활성인 앱으로 돌아가기 | 재로딩 시간, 데이터 손실 여부 |
| 안전성 | 시스템 보호 앱, 전체화면, 중간 취소 | 미개입 여부, 원래 정책 복원 |

적은 RAM을 재현하기 위해 시스템 메모리 부족을 인위적으로 심하게 유발하거나 중요한 프로세스를 종료하지 않습니다. 민감한 사용자의 PC 대신 테스트용 장비에서 수행합니다.

## 발표 가능한 기존 증거와 구분

`docs/VALIDATION.md`에 보존된 0.3.3 → 0.3.4 비교는 **RamFlow WPF UI 자체의 메모리 사용량**에 대한 측정입니다. 같은 화면 순회(3회)에서 최대 상주량 중앙값 347.6 MiB → 165.0 MiB, Private Bytes 263.5 MiB → 80.6 MiB로 기록되어 있습니다. 이는 앱 자체의 저자원화 근거이지 **다른 프로그램의 속도, 전체 시스템의 RAM 절감 또는 RAM 증설 대체**를 입증하지 않습니다.

실사용 작업의 개선은 A/B/C 프로토콜로 실제 측정한 뒤 결과·원자료·조건을 추가합니다. 결과가 나빠졌다면 그대로 보고하고 정책을 조정합니다.

## 안전·윤리·재현성

- Dry Run부터 시작합니다. 실제 Windows 설정 변경·페이지 파일 변경은 테스트 장비에서 명시적으로 확인한 경우만 수행합니다.
- 종료 시 원래 설정 복원 여부를 확인하고, 실패 시 기록을 보존합니다.
- 작업 중인 파일의 저장 여부를 확인하고 개인 정보가 드러나는 프로세스 이름·경로·스크린샷은 공유 자료에서 익명화합니다.
- 원본 CSV/JSON은 실험 장비에 보관하고, 외부 공개 자료에는 민감 정보를 제거한 표와 측정 방법만 담습니다.
