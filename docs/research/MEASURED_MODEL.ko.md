# 실측 비용 모델과 예측 거부

기존 `CarpPolicy`를 재구현하지 않고 `MeasuredCostModel.cs`·`CalibratedObservationSource.cs`를 추가했다. 정책 버전은 `0.2.0-research`, 최종 연구 빌드는 `0.4.0-carp.2`다. 현재 실제 앱 모델이 아니라 **격리한 합성 작업용 모델 경로**를 검증했다. 신뢰 가능한 모델 후보를 얻었다는 결론은 아직 없다.

## 실제 입력과 분리

`CostObservation`은 세션 블록·fit/validation 구분·하드웨어 구성/작업 지문·실제 경합 분류·조치·원시 센서 특징·전경 작업 p95·배경 반복/초·재접근 대리 지연·호스트 CPU 비용을 받는다. 같은 블록의 무개입과 후보를 대응시킨다. 요청 100개를 독립 표본 100개로 바꾸지 않는다.

학습기는 `fit`과 `validation`만 받으며 `test`·`pilot`은 거부한다. 같은 블록이 두 분할에 나타나거나 후보 측정이 중복되면 거부한다. 모델마다 하드웨어/작업은 하나이고, 여러 모델은 CLI `train --output`으로 분리 저장한다. 없는 무개입 쌍, 0인 기준 처리율, 잘못된 수치로 상대 효과를 만들지 않는다. CPU 경합의 메모리 후보, RAM 경합의 CPU 후보는 CARP 모델에서 제외하되 원시 측정은 보존한다.

## 추정식과 검증

전경 이득은 `1 − candidate_p95 / baseline_p95`, 배경 손실은 `1 − candidate_rate / baseline_rate`다. 두 값은 [-1,1]로 제한하고 음의 이득도 학습 자료에 보존한다. 재접근 위험은 `candidate_probe / baseline_probe − 1`의 양의 부분을 [0,1]로 제한한다. probe는 SHA/page-walk와 스케줄링을 포함하는 합성 대리 지연이며 **디스크 hard fault 지연이 아니다**. 관리 비용은 관찰 창에서 측정한 호스트 CPU 시간/벽시계/논리 CPU 수다. 호스트에는 오케스트레이션 비용도 포함되며 순수 setter 비용이라고 부르지 않는다.

CPU/100, 가용 RAM 비율, Commit 비율, `log(1+PagesInput)/log(10001)`의 특징 벡터를 사용한다. paging 센서 누락은 -1로 구별하며 관측된 값과 혼합하지 않는다. 같은 실제 경합·후보의 서로 다른 fit 블록 3개를 가까운 순으로 평균한다. 각 특징의 최대 차이가 0.15를 넘으면 이웃으로 쓰지 않는다. 이 반경은 안전 설정이며 실험으로 입증한 최적값이 아니다.

최소 fit 3블록·validation 3블록이 필요하다. validation은 fit 예측에 사용하지 않고 실제값과 예측값의 절대 오차를 계산하는 데만 사용한다. validation이 학습 특징 범위를 벗어나면 후보 전체를 거부한다. 예측하지 못한 행의 예측·오차는 **null**이며 오차 0이나 1을 넣지 않는다. `ValidationPredictions`에 실제 정규화 효과·예측·오차·거부 이유를 블록별로 남긴다. MAE는 예측 가능한 validation 행에 한정되며 전체 후보 채택 여부와 분리해 해석한다.

각 항의 validation 절대 오차 90% 경험 분위수를 여유로 사용한다. CARP에 전달할 때 이득은 낮추고 손실·재접근·관리 비용은 높인다. `Quality = 1 − max(error bound)`이며 기본 0.8 이상, 각 MAE 0.15 이하를 요구한다. **이 quality 숫자는 확률·95% CI·공식 보장값이 아니다.** 적은 블록의 경험 보정이며 최종 본실험 전 충분한 독립 보정과 기준 동결이 필요하다.

다른 하드웨어 구성/작업 지문·미학습 경합·특징 범위 밖·누락 센서 조합·검증 실패에서는 후보를 반환하지 않는다. 모델 파일은 schema 3·내용 해시·분할 ID·데이터 해시를 동결하고 기존 파일을 덮어쓰지 않는다. 해시는 내용 일관성 수단이며 데이터의 진실성이나 저자 검증을 보증하지 않는다.

## 엔진과 진행량 연결

엔진은 실제 EMA/CPU 히스테리시스에서 판단한 경합을 `IPolicyContextObservationSource`에 전달한다. 소스가 경합을 임의로 다시 추정하거나 시스템 CPU 수치를 덮어쓰지 않는다. 새 `CarpEvidence`는 현재 PID+생성 시각·실제 관측 UTC에 연결된다. 측정하지 않은 전경 입력 지연 필드는 null이다.

계측 가능한 자체 작업은 실제 누적 완료량·작업 epoch·관측 시각을 제공한다. fit 무개입 처리율에서 만든 기준 진행률이 있으면 심한 진행률 저하도 기아 가드에 전달할 수 있다. 외부 프로세스는 이런 카운터를 갖는다고 가정하지 않으며 최대 제한 시간으로 보호한다. 모델이 거부돼도 이것을 성공 예측이나 성능 개선으로 바꾸지 않는다.

## 실제 파일럿 결과와 한계

독립 관측기 구성의 건강 상태에서 fit 3·validation 3 대응 블록, 4후보 × 6블록 = 24개 시행을 수행했다. 24개 모두 완료·원복했고, 후보 3개는 모두 검증 범위 조건으로 거부됐다. 일부 validation에서 예측 가능한 행의 오차는 존재하지만 모든 validation 지원 조건을 만족하지 않아 채택할 수 없다. CPU 전 코어 예비 시도는 요청 수 확보 실패로 중단했고 유효 CPU 모델을 만들지 않았다. RAM/혼합 압박 모델은 아직 실제 검증하지 않았다.

이 자료로 가중치를 사후 조정하거나 반경을 넓혀 통과시키지 않았다. 건강 상태에서 CARP가 무개입한 것이 동작 확인이며, V1·고정 정책 대비 우월성은 보류한다. 원시 기록·모델 거부·실패 시도·최종 비교는 [추가 구현 검증](PHASE2_RESULTS.ko.md)을 따른다.

## CPU 압박 후속 파일럿에서 드러난 문제

12스레드 실측 보정27회와 비교18회를 추가 실행했다. CPU 단독 후보는 검증3블록 중1개의 지원 범위 이탈로 거부됐다. CPU+EcoQoS의 조치 후 경합이 healthy로 바뀌면 현재 같은 경합 기준선 pairing에서 후보가 빠진다. 이는 조치 전 상태에 대한 효과를 학습해야 하는 연구 설계의 미완료 부분이다. 학습 입력·후속 비교 적격성은 조치 전 독립 관측 창으로 고정하고, 조치 후 상태 변화는 결과로 보존하는 설계를 구현·검증하기 전까지 모델과 현재 비교 분석을 우위 근거로 사용하지 않는다. 원본을 재라벨링하거나 임계값을 완화하지 않았다. [실제 CPU 파일럿과 프로토콜 이탈](PHASE3_CPU_PILOT.ko.md)을 참고한다.

위 Phase3 문제는 [조치 전 고정 프로토콜](PRE_INTERVENTION_PROTOCOL.ko.md)에서 수정했다. 새 workload v2·schema3의 [후속 자료](PHASE4_PRE_INTERVENTION_RESULTS.ko.md)는 조치 전 센서 중앙값/경합으로 학습했고 CPU·CPU+EcoQoS 두 후보의 독립 validation3블록이 기존 기준을 통과했다. 비교에서는 신뢰 모델을 받았지만 보수적 이득이 비용을 넘지 않아 CARP가 무개입했다. 이전 자료/모델은 재학습에 합치지 않았으며 실제 개입 우위·외부 일반화·본실험 성공은 여전히 미검증이다.
