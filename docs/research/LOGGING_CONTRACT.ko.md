# 검사 전 기록 경로와 무결성 검증

이 변경은 연구 실행기의 기록 신뢰성을 보완한다. 성능 우위 검증이나 Chrome/VS Code 새 비교 실험을 수행한 변경이 아니다. 기존 실험·원본·main/연구 기준선을 보존한다. 실제 앱용 새 실행기를 만들 때도 아래 계약을 연결해야 하며, 과거에 확보하지 못한 원시 로그가 이 변경으로 복구되는 것은 아니다.

## 발견한 누락과 수정

- 초기 인자/소스/바이너리 준비가 기존 try보다 앞에 있어 준비 실패가 stdout/stderr에만 남을 수 있었다. 출력 폴더를 독점 생성한 직후 실행 ID·호스트 PID/생성 시각·인자·런타임·OS·바이너리 해시와 시작 이벤트를 먼저 기록한다. 출력 폴더 자체를 만들 수 없는 오류는 호출자의 stderr 기록이 필요하다.
- 시스템 스냅샷과 부모 왕복 시간이 최종 요약까지 메모리에만 있었다. 요청 시작/응답/오류와 측정에 채택한 전경 원시값, 시스템 상태를 JSONL에 즉시 추가한다. UTC와 단조 시계 tick을 함께 기록한다.
- 자식 stderr가 지속적으로 소비·보존되지 않았다. stdout 원본과 별도 stderr JSONL을 저장하고, 역할·PID·생성 시각·실행 파일/해시·명령 인자를 시작 이벤트에 결합한다.
- 결과가 정리보다 먼저 저장돼 정리 실패가 성공 요약 뒤에 발생할 수 있었다. 각 정리를 개별 시도해 한 오류로 나머지가 생략되지 않게 하고 결과를 정리 이후에 저장한다. 예기치 않은 자식 종료와 오류 종료도 성공 정리로 처리하지 않는다.
- 직접 실행에서 commit이 unknown으로 남을 수 있었다. 실제 캡처한 Git commit을 기본으로 사용하고 명시 인자와 다르면 개입 전에 거부한다. dirty 여부와 선택한 소스 파일의 실제 사본/해시를 보존한다. 초기 인자 오류에도 호스트·Core 바이너리 해시는 남긴다.
- 실행기 stdout/stderr와 시작/종료 메타데이터를 부모 폴더에 저장한다. 취소는 먼저 cancel.request로 전달해 정상 정리 기회를 주고 강제 종료 시 원복 확인을 주장하지 않는다.

## 한 시행의 주요 파일

| 파일 | 의미 |
|---|---|
| run-manifest.json | 실행 ID, 인자, 호스트 PID+생성 시각, 런타임/OS/바이너리 해시, 시계 기준 |
| trial-events.jsonl | 순번·UTC·단조 시각을 가진 단계, 생성 프로세스, 요청, 시스템 상태, 측정 원시값, 실패, 정리, 종료 |
| started.json, source/ | 블록/조건/seed/부하/소스 commit·dirty·사본/바이너리·모델 해시 |
| foreground-raw.jsonl, background-raw.jsonl | 자식이 실제 반환한 응답/진행량 |
| *.stderr.jsonl | 자식의 오류 출력과 수신 시각 |
| pre-intervention.json | 조치 전 실제 관측 창과 특징 |
| effective-settings.json | 실제 설정과 설정 해시 |
| resource-original.json, resource-final.json | 배경 PID+생성 시각, 원래/최종 설정, 원복 readback |
| audit/events.jsonl, audit/events.csv | 정책 판단, 실제 적용/복원 결과. 순번·시각·대상·정책·설정 해시·결과를 교차 검사 |
| outcome.json | 정리 후 결과. 실패/중단과 부분 자료도 보존 |
| failure.json, batch.failure.json | 준비/최종 기록 또는 배치 실패의 예외와 단계 |
| completion.json | 종료 상태, 정리 완료 여부, 로그 오류, 이벤트 수와 로그 쓰기 비용 |
| artifact-index.json | 모든 기록을 닫은 뒤 파일별 길이·SHA-256 목록 |

미종료 기록은 완료 표시가 없다. 다음 실행은 새 폴더를 사용하며 기존 파일을 덮어쓰지 않는다. 강제 중단 시에도 이미 쓴 원시 기록을 남기고 완료·원복 여부는 미확인으로 처리한다. 과거 결과에 새 완료 표시나 해시 목록을 소급 생성하지 않는다.

## 학습·분석 전 검증

```powershell
python scripts/research_logcheck.py --input work/새시행
python scripts/research_logcheck.py --input work/새배치 --recursive
```

검증기는 파일 누락/변조, 완료 표시, 실행 ID·연속 순번·단조 시각, 요청 짝, 전경 원시값–요약 일치, 감사 CSV–JSON의 순번/시각/대상/내용을 확인한다. 실패 기록이 완결됐다는 것과 성능 평가에 사용할 수 있다는 것은 별개다. `ok=true, status=failed`는 잘 보존된 실패이며 `performance_ready=false`다. 준비 도중 계획도 만들지 못한 배치 등은 필요한 자료 부족도 명시한다.

새 evidence-v1 자료는 분석기와 학습기에서 완료/무결성 조건을 확인한다. 학습기는 실패·미원복·미완결 또는 해시가 바뀐 새 자료를 거부한다. 과거 자료는 기존 표시를 유지하고 새 workload ID와 합치지 않는다. 인덱스의 fixture-bin 파일은 바이너리 해시만 남기는 아카이브를 허용하되 빠진 바이너리를 경고한다. 원시 로그·소스·설정은 필수다.

## 보존 한계와 오버헤드

이벤트마다 OS 버퍼까지 flush하고 단계 경계에서 durable flush를 요청한다. 전원 상실·장치 고장 때 모든 표본과 복원을 보장하지 않는다. 디스크 기록 자체가 실패하면 성공으로 통과시키지 않으며 외부 실행기의 stderr와 미완료 파일을 조사한다. SHA-256은 파일 일관성 검사이며 실험의 과학적 타당성이나 작성자의 진실성을 증명하지 않는다.

상세 기록은 측정 오버헤드를 바꾸므로 workload ID에 evidence-v1을 추가했다. 이전 파일럿과 같은 계측 조건으로 취급하지 않는다. completion의 log_write_ms는 이벤트 직렬화/쓰기/flush 벽시계 비용이며 소스 복사·인덱싱 전체 비용이나 CPU 사용량이 아니다. 다음 성능 실험에서는 같은 기록 설정을 모든 비교군에 적용하고 계측기 비용을 분리 보고해야 한다.

검증용 Windows 프로세스만 사용해 정상 완료·준비 실패·잘못된 commit·계획 전 배치 실패·로그 전용 자식 강제 중단·무개입 시행의 정상 취소를 확인한다. 실제 앱 성능 수치나 효과를 생성하지 않는다. CI가 실패해도 진단 로그 artifact를 업로드하도록 구성한다.
