# 동일 시간 예산의 개입 배치 비교 — 측정 전 고정 v1

기존 36슬롯 A/B/C 연구에서 V1은 고정 제어보다 적은 시간 동안 개입했다. 배경 처리량 보존이 단순히 개입량 차이인지, 개입 시점 선택의 가치인지 분리하지 못했다. 이번 보강은 RAM Flow 연구 실행기 안에서 **같은 요청 예산을 어디에 배치하는지**만 비교한다. 제품 기본 정책이나 전체 CARP를 교체하지 않는다. 기존 자료는 개발 배경으로만 쓰고 새 결과와 합산하지 않는다.

- 프로필 `real-app-budget-v1`. B 고정 주기 / C 실제 응답 피드백. 두 조건 모두 실제 엔진·트레이 및 동일한 CPU BelowNormal, EcoQoS 켬, 메모리 우선순위 3 조합을 사용한다. 강제 Working Set 축소 없음.
- 단일 PC, Chrome 생성 대시보드 / VS Code 생성 TypeScript 문서. 앱별 6개 대응 블록, 총 24세션. BC/CB 순서 각 3회, 앱 순서 및 고정 마스크 회전은 seed 20261113으로 측정 전에 고정한다. 합성 CPU 부하는 기존 검증된 정상 QoS xorshift 계산 작업이다. 실 빌드·일반 사용자 작업 완료시간 결과로 확대하지 않는다.
- Normal → Contention → Recovery 각 10초, 활성 배경 스레드 1 → 14 → 1. Normal은 기능별 최소 20개 요청까지 연장할 수 있다. Contention 측정의 요청 루프와 별도 절대 단조시계 제어 루프를 사용한다. 시스템·PID·활성 작업 보호 및 원복 저널은 항상 우선한다.
- 20개의 0.5초 epoch 중 9개 ON을 요청한다. 고정 마스크는 `[0,1,2,5,6,10,11,15,16]`, 블록별 사전 지정 회전을 적용한다. 피드백은 각 세션 Normal p95에 대한 실제 기능 응답 비율의 EMA(α=0.3), 기능별 EMA 중 최댓값을 사용한다. 진입 1.25, 이탈 1.10, 최소 ON 2 epoch. 이 값은 공학적 고정값이며 예상 개선율·학습된 확률·검증된 사용자 SLO가 아니다.
- 남은 epoch와 남은 예산이 같으면 C는 꼬리에서 강제 할당한다. 따라서 낮은 위험에서도 개입할 수 있다. **동일량의 배치 비교를 위한 제한**이며 무개입 최적화나 서비스용 정책으로 주장하지 않는다. 신뢰할 수 있는 실제 응답이 없거나 1.5초보다 오래되면 예산보다 무개입이 우선한다. 메모리 압박 Moderate 이상에서도 개입하지 않는다. 요청한 예산을 못 채운 실행은 실패로 보존한다.
- 세션 적격: 요청 9 epoch, 실제 성공 OS readback 상태 ON 시간 4.5초 ±0.1초, 각 제어 deadline 지연 ≤0.1초, 제어 종료 후 원복. 대응 적격: B/C 실제 ON 시간 차이 ≤0.15초. 원시 시각으로 독립 재계산하며 요약과 불일치하면 인정하지 않는다. 같은 wall time은 같은 CPU 할당량·배경 손실을 뜻하지 않는다.
- 주 비교는 Contention C−B 기능별 p95와 배경 유효 처리율을 함께 보고한다. 단일 지표 개선만으로 성공을 판정하지 않는다. 응답성 동등성 허용치는 근거 부족으로 미설정이며 비열등성/동등성 검정을 하지 않는다. 대응 블록 bootstrap 10,000회, seed 고정, 탐색적 95% 주변 CI·다중성 미보정. 요청은 독립 N으로 계산하지 않는다. 보호 오개입, 원복 실패, 오버헤드도 함께 보고한다.
- 실패 재시도 없음. 무결성·원복을 확인하지 못하거나 연속 2세션 실패 시 나머지는 미실행 처리한다. 부정적 결과를 이유로 매개변수나 허용치를 변경하지 않는다. 우위가 없으면 그 결과로 이번 비교를 닫는다.

실행 전 소스 커밋, Release 빌드 및 회귀검증 후 실행:

```powershell
python -u scripts/research_budget_batch.py --output work/real-app-budget-batch-20261112 --seed 20261113
```

실행기는 깨끗한 소스·바이너리 SHA, 계획 SHA, 안전 사전 부하 검증, 각 세션의 fd17548 seal/index 및 raw↔summary를 확인한다. 격리 앱 창만 전경으로 활성화하고 측정 중 다른 테스트·빌드를 실행하지 않는다. 로그에는 원래 값, 모든 OS 요청/readback, 각 epoch의 관측 ID·EMA·선택 이유, 실제 제어 시각, 독립 관측기·엔진 호스트/트레이 자원 비용을 남긴다. 분석 출력은 동일 경로 `analysis/`에 생성된다. 재실행으로 기존 경로를 덮어쓰지 않는다.
