# 조치 전 관측으로 고정한 연구 프로토콜

Phase3에서 조치가 경합 상태 자체를 바꾸면 후보가 학습/분석에서 빠지는 문제를 확인했다. 기존 원본을 재라벨링하지 않고 새 workload v2·outcome schema3으로 분리한다.

- Engine 생성/설정 전에 기본5초 동안 같은 전경 요청·배경 부하를 실행한다. 0.5초 간격의 원시 센서와 시각을 저장하고, 관측 경합의80% 이상 일치와 목표 상태 도달을 요구한다. 센서5개·시각 간격2초 이상이 최소 조건이다. 이 짧은 창은 미래 정상성을 보장하지 않는다.
- 조치 전 창이 부적격하면 개입하지 않고 실패·원복 상태를 보존한다. 조치 전 파일을 먼저 쓰고 해시를 기록한 뒤에 Engine을 생성한다. 장치/작업별 모델 신뢰도·보호·신원·Dry Run·원복 검사는 유지한다.
- 학습 Contention과 Features는 고정한 조치 전 창에서만 만든다. 특징값은 각 센서 성분의 관측 중앙값이다. page-input 결측은 null로 유지한다. 모델 지원 반경·오차·품질 기준은 Phase3 기본값을 바꾸지 않는다.
- `eligibility_regime`과 `pre_intervention`은 분석 코호트·적격성 기준이다. 기존 `regime`, `regime_attained`와 새 `post_regime_stable`·`post_regime_samples`는 조치 후 결과로 보존한다. 조치 후 상태 전환만으로 무효 처리하지 않는다.
- 분석기는 schema3에서 창/처치 시각 순서·최소 표본/길이·기준 일관성을 검사한다. schema2는 역사적 기준을 유지하고 `regime_basis`를 달리해 두 버전을 합치지 않는다. 실패·정확성·원복·중복·결측 검사는 유지한다.
- 재실험은 새 경로와 seed를 사용한다. fit/validation과 정책 비교는 분리한다. 본실험 사전 등록이 아닌 단일 PC 합성 파일럿이다. 측정 중 로컬 빌드·테스트·분석을 실행하지 않는다. 측정기가 요구하는 작업 외에 사용자의 다른 활동이 없음을 보증하지는 않는다.

이 수정은 사후 상태에 따른 선택 편향 경로를 제거하는 구현이다. 비용 모델의 예측 정확도, CARP의 우위나 실제 앱 효과를 입증한 것은 아니다. 조치 전 window 특징과 동적 운영 센서 사이의 지원 범위 차이도 새 파일럿에서 거부 사유로 확인해야 한다.

재실험 중 관측기 phase 파일의 교체에서 AccessDenied가1회 발생했다. 파일의 delete sharing을 막는 읽기 핸들로 같은 예외를 재현하고, 알려진 접근/잠금 오류만10ms 간격으로 최대19회 재시도하도록 보완했다. 영구 오류는 약190ms 대기 후 실패를 유지하며 이전 파일·호출자의 복원 경로를 보존한다. 실제 발생 원인이 외부 읽기 핸들이었는지까지 확정한 것은 아니다. 교체 재시도 수·경과 시간·성공/실패를 후속 outcome에 기록한다. 기존 측정 자료는 이 보완 전 바이너리 자료로 계속 식별한다.
