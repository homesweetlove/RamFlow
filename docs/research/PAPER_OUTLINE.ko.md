# 정규 연구논문 구성안과 빈 보고 양식

작성·출처 확인 기준일: **2026-11-10**. 상태: 연구 준비 초안. 본 문서는 논문 완성본·제출본이 아니다. CARP 성능 결과·확정 표본수·승인·저자·기여·지원금을 만들어 넣지 않았다. 우선 대상은 **정보처리학회 논문지(TKIPS) 정규 연구논문**이며 대안은 **한국컴퓨터정보학회논문지(JKSCI)**, **한국정보기술학회논문지(JKIIT)**다. JKIICE와 혼동하지 않는다.

## 1. 논문의 중심 질문

Windows의 명시적 배경 작업을 제어할 때, 전경 작업 응답을 보호하면서 배경 진행 손실·재접근·관리 비용을 제한할 수 있는가? 핵심은 **비용 인지 정책과 전경/배경 절충의 검증**이다. “RAM을 정리해 PC가 빨라진다”는 제품 소개를 논문 문제로 삼지 않는다.

작업 제목 후보: **Windows 전경·배경 작업의 비용을 고려한 자원 정책 설계 및 평가**. “최초”, “최적”, “전체 성능 향상”, 결과를 전제하는 개선율을 제목에 넣지 않는다. CARP 약어의 정식 확장은 실제 구현·저자 합의 후 결정한다.

## 2. 준비 문서와 근거의 우선순위

- [PROTOCOL.ko.md](PROTOCOL.ko.md): 비교 조건·모델·파일럿/동결·표본 계획·결측·통계·실패 보존의 기준. 실행 뒤에는 실제 수행과 편차를 구분해 Methods를 작성한다.
- [RELATED_WORK.ko.md](RELATED_WORK.ko.md): MemClean, Mem Reduct, Microsoft QoS, Acclaim, Heracles의 확인 범위·출처·반례·신규성 한계.
- [JOURNALS.ko.md](JOURNALS.ko.md): 공식 KCI 식별, 현재 열람한 규정·비용·AI/기여 공개 및 미확인 사항.
- [SCARCITY_STUDY](../SCARCITY_STUDY.ko.md), [BACKGROUND_CONTROL_STUDY](../BACKGROUND_CONTROL_STUDY.ko.md), [REAL_APP_STUDY](../REAL_APP_STUDY.ko.md): 서로 다른 빌드/작업의 기존 내부 예비 기록. CARP 본 표본과 섞지 않는다.

주장은 원시 증거→고정 분석→본문→초록 순으로 확정한다. 문헌 초록·README의 작성자 주장을 독립 검증 결과로 바꾸지 않는다. 웹 열람과 사람의 원문 대조·최종 승인도 구분한다.

현재 구현은 `0.4.0-carp.1`, `Settings.PolicyName=v1` 기본값이며 fixed/carp가 선택 가능하다. CARP는 외부 JSON 관측을 Engine 생성자에서 주입하는 계약만 있고 **실제 앱 비용 모델·성능 파일럿은 없다**. 네 가중치 1, stable 3, cooldown 30초, evidence age 10초, 모델 독립 블록 최소 3·confidence 0.8은 미보정 기본값이다. 모델 메타데이터의 최소 블록 수와 통계 표본수, confidence 숫자와 CI를 혼동하지 않는다. 기본 관측 부재의 자원 무개입, 큐의 시작 보류 가드, `ResearchReplay`의 무조치 결정을 별도로 설명한다.

이 작업의 Windows+IPC **274개 assertion 통과** 기록에는 합성 입력을 사용한 CARP 자체 테스트 자식의 실제 setter·원복이 포함된다. 이 문서 작업은 이를 재실행하지 않았으며, 해당 검증을 앱 응답 개선이나 비용 모델 보정 결과로 보고하지 않는다. [기준선 감사](BASELINE_AUDIT.ko.md)의 기존 11월 원시 benchmark 디렉터리 미확보와 공개 ZIP `e9b86e1f…`/옛 로컬 재포장본 `d4d2a1c9…` 해시 불일치도 원고의 재현 한계에 포함한다. 공개 release metadata 확인을 ZIP 자체 재다운로드 검증으로 바꾸지 않는다.

## 3. 절별 구성

### 1. 서론

전경 응답과 background throughput이 경쟁하는 구체적 작업 상황을 제시한다. 불필요한 페이지 회수와 무조건적인 배경 억제의 비용을 문제로 설명한다. 연구 질문·한정된 대상·검증할 기여를 명시한다. 기존 기록은 문제 발견 과정의 예비 자료로만 인용하며 신규 실험을 이미 끝낸 듯한 과거형을 쓰지 않는다.

후보 기여는 (1) 이득·배경 비용·재접근·관리 비용 및 무개입을 명시한 정책 계약, (2) Windows의 제한된 조치 권한과 신원/복구 감사 구현, (3) 고정/V1/CARP/절제 및 정상·압박 조건을 함께 다루는 평가다. 최종 원고에서는 실제 구현·데이터가 입증한 항목만 남긴다.

### 2. 배경과 관련 연구

Windows working set/private commit/page fault, CPU 우선순위·메모리 우선순위·EcoQoS의 차이를 설명한다. MemClean에는 전경 보호와 EcoQoS 관련 코드가 있으므로 이를 없는 기능으로 취급하지 않는다. Mem Reduct의 정리 경로와 성능 효과를 구분한다. Acclaim의 전경 인지·재접근 문제와 Heracles의 지연/배경 자원 절충을 선행 연구로 인정한다. 플랫폼·계층·조치·목적함수·평가 범위를 표로 비교한다.

Acclaim 공식 PDF 직접 열람은 이번 조사에서 403으로 실패했다. 현재 검증한 발표 페이지 이상의 실험 상세는 원문 확인 전 쓰지 않는다. 확인된 다섯 대상만으로 모든 기존 연구의 부재를 주장하지 않는다.

### 3. 문제 정의와 비용 인지 정책

대상 프로세스의 명시적 동의/지정, 전경 및 의존성 모델, 관측 가능한 입력·단위·생성 신원·유효기간을 정의한다. `gL/cB/cR/cO`, 정규화·가중치·예측 horizon·불확실성, 비용 한계·무개입 후보를 실제 구현과 대응시킨다. 추정 점수와 실측 latency를 별도의 변수·표로 둔다.

계측/비용 모델이 비어 있으면 무개입한다는 사실을 명시한다. mock 관측으로 동작하는 정책 시험은 기능 검증이고 실 앱의 효용 모델 검증이 아니다. 본 실험 데이터로 가중치를 사후 선택하는 누수를 막는 절차를 설명한다.

### 4. Windows 구현과 실패 처리

정책 판단과 엔진의 최종 보호 재확인·원래 값 저널·적용·readback·복구를 구분한다. V1 보존·비교용 고정 정책·CARP 선택, 감사 로그·manifest·결측 경로를 보여 준다. 실제 파일·함수·코드 hash를 최종 코드와 대조해 채운다.

CPU/메모리/EcoQoS 조치의 지원 조건과 권한, PID 재사용·전경 변경·오래된 관측·부분 성공·감사 실패·복구 실패를 다룬다. 주 평가에서 강제 working set 축소·CPU Sets·큐가 꺼져 있음을 명시한다. 큐는 별도 입장 제어 실험으로 분리한다. 우선순위 원복과 제거된 페이지의 즉시 복구는 다른 개념이다.

현 fixed는 CPU·EcoQoS만, V1은 메모리 우선순위도 포함하는 기존 묶음이다. C–E의 차이에 조치 구성 차이가 포함됨을 밝히고, 조치별 F로 판단 기여를 추가 해석한다. CARP의 score/entry margin 선택은 별도 hard background budget을 보장하지 않는다. 논문의 손실 한계는 평가 기준이다. 큐는 CPU 압박·예약 여유에서 시작을 보류하는 가드이며 비용 최적 큐 스케줄러로 서술하지 않는다.

### 5. 평가 방법

실물 RAM 8/16/24 GB 이상 층, 장치별 usable RAM·CPU·SSD·전원·OS/app 버전, CPU/RAM 중심/mixed/healthy 조건을 기록한다. 합성 S, 실제 앱+합성 배경 H, 실제 전경+실제 배경 R을 분리한다. 없는 장치/측정은 미실험으로 남긴다.

A none, B dry, C fixed, D 공통 actuator 프로필의 V1, E CARP, F 개별 절제를 정의한다. 프로세스 외피·입력·부하·관측을 통제하고, 조건마다 자원 압박을 재조절하지 않는다. 독립 device-day 대응 블록, 균형 무작위 순서, warm/cold 구분·washout·원복 검증·전경 재전환 probe를 설명한다.

파일럿과 새 확증 표본, 동결 시점·N 결정·정밀도·공동 검정력, 실패/기술 무효·대체 한도·결측 처리·편차를 보고한다. 블록별 p95와 deadline-capped task-loss를 성공 latency와 구분한다. 요청 수는 독립 표본 수가 아니다. 주 8개 가설·Holm·개별/동시 CI·원단위 효과·Pareto를 프로토콜과 일치시킨다.

### 6. 결과

실제 수집 후 다음 순서로 작성한다: 전체 시도 흐름·누락/중단/실패 → 주 R mixed 대비와 gate → 배경 비용·재접근·복구 → healthy 비용 → CPU/RAM 기전·장치 이질성 → 절제 → 별도 Q 큐 실험(수행한 경우). 결과가 없는 소절에 기대 개선율이나 “유의한 향상” 문장을 넣지 않는다.

부호가 반대인 블록·장치·작업, 무개입·0 진행·오답·timeout·정책 유발 중단을 표에서 남긴다. 보조 탐색 결과가 좋더라도 실패한 주 endpoint를 대체하지 않는다. 통계적으로 비유의한 결과를 동등/안전이라고 부르지 않는다.

### 7. 논의와 타당도 위협

CPU 경쟁 완화와 메모리 우선순위 효과를 분리해 해석한다. 고정 policy와 같은 절충이면 그 사실을 보고한다. 전경의 개선이 배경의 큰 손실을 요구하면 비용을 결론에 포함한다. 도구 자체와 외부 observer의 비용, 프로세스/앱 의존성, 캐시·열·OS 자동 정책·timer·입력 자동화·tail 추정·결측 선택 편향을 논의한다.

RAM 용량이 다른 PC의 CPU/메모리 채널 차이, 적은 장치 수, 생성 작업·실제 workload 범위, 앱 endpoint의 UI 지연 대리성, 비용 모델의 분포 변화, 설정 변경과 실제 작업 상태의 복구 차이를 제한으로 둔다. 이 결과에서 사용자 만족·생산성·에너지 절약을 직접 측정하지 않았다면 추정하지 않는다.

### 8. 결론

관측된 범위·대비·불확실성·배경 비용을 포함한 결론만 작성한다. 주요 gate나 모델 연결이 미완료라면 검증 제한을 결론의 일부로 둔다. “모든 Windows PC”, “RAM 부족 해결”, “총 처리량 증가”로 확대하지 않는다.

이 문서군에는 AI 보조 조사·설계·초안 작성이 사용됐다. 위 빈 선언은 “AI 미사용”을 뜻하지 않는다. 실제 사용 기록을 보존하고 대상지 요구에 맞는 사실 진술로 작성해야 한다. 특히 JKSCI의 [2026년 AI 규정](https://ksci.re.kr/homepage/custom/rules9)은 보조 사용 제한과 사용 표시를 함께 규정하므로, 공개 문구 추가만으로 투고 적합성이 해결됐다고 간주하지 않는다. TKIPS/JKIIT의 AI 전용 요구는 이번 열람 범위에서 미확인이다.

## 7. 투고 준비 완료의 조건

- 실제 앱의 비용 관측·모델 연결, 고정/V1/CARP/절제의 설정·감사·복구 증거가 코드와 일치한다.
- 파일럿과 확증 자료가 분리되고, 가중치·한계·표본 계획·비교 목록이 본 표본 수집 전 동결돼 있다.
- 누락·실패를 포함한 전체 장부에서 표/그림/CI·효과크기·Holm 결과를 재생성할 수 있다.
- 문헌의 정확한 주장·서지·URL·확인 범위를 사람이 검증했다. Acclaim 원문 상세와 추가 관련 연구 검색을 완료했다.
- 실제 투고일의 KCI 상태·정규논문 양식·비용·회원/접수 경로·AI 공개 요구·선행 공개 허용 범위를 재확인했다.
- 실제 사람 저자 전원이 기여·원고·선언을 승인했다. 이 초안의 존재나 자동 검사 통과가 사람의 승인을 대신하지 않는다.

현재 위 조건의 완료를 선언하지 않는다. [TKIPS Authors](https://tkips.kips.or.kr/static/instruction), [TKIPS 범위](https://tkips.kips.or.kr/static/aim-scope), [JKSCI 투고](https://ksci.re.kr/homepage/custom/rules8), [JKIIT 투고](https://ki-it.or.kr/homepage/custom/summisregul)를 2026-11-10 열람했으며, 상세 미확인 사항은 [학술지 조사](JOURNALS.ko.md)에 남겼다.
